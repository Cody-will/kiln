# Self-hosting plan

The compiler is written in Rust. The plan is to rewrite it in Kiln one
stage at a time, front to back. Each stage is checked differentially
against the Rust implementation of the same stage before anything
depends on it. The Rust compiler stays the reference (and the bootstrap
compiler) until the Kiln one can build itself.

## Layout

`compiler/` is an ordinary Kiln package (`kilnc`):

- `src/token.kn`: token kinds, keywords, the statement-ending rule.
- `src/lexer.kn`: the lexer (port of `crates/kiln_lexer/src/lexer.rs`).
- `src/ast.kn`: the syntax tree (port of `crates/kiln_parser/src/ast.rs`,
  same names, fields, and variant shapes).
- `src/parser.kn`: the parser (port of `crates/kiln_parser/src/parser.rs`),
  including error recovery and every diagnostic message.
- `src/debug.kn`: writes the AST in the canonical dump format.
- `src/escape.kn`: generated by `tools/gen_escape_debug.rs`; the code
  points Rust's `{:?}` writes as `\u{..}`, so string and char payloads
  in the dump are escaped the same way.
- `src/derive.kn`: derive expansion (port of `kiln_parser/src/derive.rs`).
- `src/codegen.kn`: native code generation (port of `crates/kiln_codegen`),
  writing LLVM IR text.
- `src/main.kn`: the driver. `kilnc <file.kn>...` prints the canonical
  token dump; `kilnc --ast <file.kn>...` prints the canonical AST dump.
  `kilnc --emit-llvm <file.kn>` prints a program's LLVM IR and
  `kilnc --build [--release] <file.kn> -o <out>` compiles it to an
  executable (see "Code generation and bootstrap" below). Both load
  multi-file packages: `mod name` reads `name.kn` or `name/mod.kn`, as
  `kiln_parser::package` does.

Build it with `kiln build` in `compiler/`.

## Differential testing

Each stage gets a canonical text dump implemented on both sides. For the
lexer, that is `kiln_lexer::dump`, printed by `kiln lex --dump <file>`:
one line per token with its byte span and payload, then doc comments,
then errors. `crates/kiln_cli/tests/lexer_diff.rs` builds `kilnc`, runs
it on every `.kn` file in the repository, and requires its output to be
identical. That includes std, examples, tests, benchmarks, the compiler
itself, and the edge-case corpus in `tests/lexer/` (every lexical error
path, all literal forms, CRLF and Unicode whitespace). It runs with
`cargo test`.

For the parser, the dump is `kiln_parser::dump`, printed by
`kiln parse --dump <file>`: the pretty `{:#?}` of the `File` before derive
expansion, with each `Span { start, end }` collapsed to `start..end` on
one line, followed by one `error <start>..<end>: <message>` line per
diagnostic (lexer errors first, then parser errors in the order they were
reported). `crates/kiln_cli/tests/parser_diff.rs` runs `kilnc --ast` on
every `.kn` file in the repository plus the corpus in `tests/parser/`:
`syntax.kn` covers every syntactic form, and `errors.kn` covers the error
messages and recovery paths. The output must match byte for byte.

Derive expansion is checked twice: `kilnc --derive` against
`kiln parse --dump-derive` (the generated source text, for every file),
and `kilnc --ast-expanded` against `kiln parse --dump-expanded` (the AST
with the generated items appended, for every file deriving `Json`, one
fresh process per file because generated spans are allocated from a
per-process counter starting at `1 << 42`). `tests/parser/derive.kn`
covers every field shape, generics, nested modules, and the error for a
non-type item.

For name resolution, `kiln resolve --dump <file>`
(`kiln_resolve::dump`) prints the whole `Resolved` table: every
definition (`d<id> <kind> <name> <span> <vis> m<module>`), local,
path resolution and binding (sorted by span), impl, function body,
static and constant function, then each error with its help line.
Entries inside the prelude and standard library are left out, but they
are counted in every id, so the ids check the prelude too. Both sides
parse the user file first and then the builtin source (assembled from
`crates/kiln_resolve/src/prelude.kn` and `crates/kiln_resolve/std/` in
`STD_MODULES` order; `kilnc` reads them from `$KILNC_RESOLVE_DIR`,
default `crates/kiln_resolve`), so derive spans line up.
`crates/kiln_cli/tests/resolve_diff.rs` runs `kilnc --resolve` on every
`.kn` file (one process per file) plus `tests/resolve/errors.kn`, which
covers the scope errors. The Kiln resolver keeps no references into the
AST: where Rust compares `&Item` pointers it keys by the item's span, and
a definition records the shape of its fields instead of the item.

For type checking, `kiln typeck --dump <file>` (`kiln_typeck::dump`)
prints every type error with its help line, then for each function body
outside the prelude: local types (by id), expression types (by span),
method resolutions (autoderef steps, `self` kind, receiver type, callee
and substitution), callees with their substitutions, coercions, deref
coercions, callee derefs, constant uses and `for` element types. Types
print with definition ids (`d10<usize>`, `fun(i32) bool`, `'T` for a
parameter, `?int` for an unresolved literal) so equal names can't hide a
wrong id. `crates/kiln_cli/tests/typeck_diff.rs` runs `kilnc --typeck` on
every `.kn` file plus every Kiln snippet in
`crates/kiln_typeck/src/tests.rs` (written to a temporary directory), so
the error paths are covered too. The resolver now keeps copies of the
items typeck needs (a function's declaration, an impl's header, a
definition's item and a variant). The Kiln checker keeps the per-body
state in a field of `Checker` instead of a `Body` that borrows it, and
swaps it out for trait queries made outside a body.

For MIR, `kiln mir --dump <file>` (`kiln_mir::dump`) prints every body of
every user function (closures and `spawn` blocks after their parent) with
all fields: local declarations (kind, type, name, span, mutability,
resolver id), each statement and terminator with its span, callee
substitutions, call flows, captures, bounded loops, lowering errors and
unsupported constructs. Types print as in the typeck dump; strings escape
non-printable bytes and characters print by code point, so neither side's
`Debug` formatting matters (`kiln mir` keeps the readable form).
`compiler/src/mir.kn` holds the IR and that dump, `sig.kn` the signature
lifetime rules (sets are sorted vectors) and `lower.kn` the lowering.
`Lower` holds `&mut Checker` for trait queries (`is_copy`, `Send`/`Sync`,
user `Deref` targets) plus the function's `FnResults`, which `lower_fn`
takes out of the checker while it lowers. `crates/kiln_cli/tests/mir_diff.rs`
runs `kilnc --mir` on every `.kn` file plus the Kiln snippets in the MIR,
borrow checker and type checker unit tests.

The borrow checker (`compiler/src/borrowck.kn`) ports `kiln_borrowck`: the
signature checks (undeclared lifetimes, missing lifetime specifiers) and the
per-body dataflow over the MIR from `lower.kn` (moves, initialization, loans
with non-lexical lifetimes, drops, returned references, `spawn`/scoped task
rules). Move states are sorted vectors ordered like the Rust derived `Ord`, so
diagnostics come out in the same order. `kiln borrowck --dump` prints each
diagnostic with its span, notes and help; `crates/kiln_cli/tests/borrowck_diff.rs`
checks that `kilnc --borrowck` prints the same thing for the same inputs as
`mir_diff.rs`.

## Code generation and bootstrap

`compiler/src/codegen.kn` ports `kiln_codegen`'s Cranelift lowering one to
one, but writes LLVM IR as text, which `clang` (version 15 or later, for
opaque pointers) compiles and links with the runtime library. Every MIR
local lives in an `alloca` slot and values move through memory; addresses
are `i64` values, as in Cranelift IR, converted with `inttoptr` at each
load and store. Kiln functions are `void @f(i64 ret, i64 args...)`
(closures take an environment pointer after `ret`), the entry point is
`@kn_main`, and the layouts, drop flags, panic frames, `defer`, preemption
checks on loop back-edges, glue (drop, clone, eq, cmp, hash, debug),
vtables and intrinsics follow the Rust backend. The release-only
optimizations (register ABI, inlining, slot promotion, bounds-check
elimination) and debug info are left out; clang runs with `-O1` (`-O2` for
`--release`). Integer division, 128-bit arithmetic and casts use native
LLVM instructions, like the Rust backend's LLVM path.

`kilnc --build` needs `KILN_RT`, the path of `libkiln_rt.a` (write it with
`kiln runtime --write <dir>`; `libkiln_tls.a` goes next to it and is linked
when a program uses TLS), and `KILNC_RESOLVE_DIR` (the
`crates/kiln_resolve` directory with the standard library sources).
`KILN_CLANG` picks the compiler (default `clang`).

`crates/kiln_cli/tests/codegen_diff.rs` builds every `tests/run/*.kn`
program with `kilnc --build`, runs it, and compares stdout, stderr and the
exit status with the `.out` file `kiln build` is held to (all 83 match). It
skips itself when `clang` is missing.

`make bootstrap` builds `kilnc` with the Rust `kiln` (stage 1), stage 1
builds `compiler/` (stage 2), and stage 2 builds it again (stage 3). The
target fails unless stage 2 and stage 3 are byte-identical, both the
generated IR and the linked executable. Run it on a machine with `clang`
and `make`; it takes about three minutes.

## Gaps the parser port hit

- **The formatter continued the line after `import a::*`**, indenting the
  next item, because it read the trailing `*` as a binary operator.
  *Fixed* in `kiln_fmt` (test `glob_import_does_not_continue`).
- **Other formatter bugs:** `?Sized` printed as `+?Sized`, `pub(pkg)` as
  `pub (pkg)`, and a line after a type ending in a generic `>` was
  indented as a continuation (this had mis-indented parts of std).
  *Fixed*; `tests/parser/` is in the formatter corpus test again.
- **`{:?}` on f64 differed from Rust** (`1e16` printed as
  `10000000000000000.0`). *Fixed:* Debug switches to the shortest
  exponent form outside `1e-4 <= |x| < 1e16`, as Rust does
  (`tests/run/float_debug.kn`). Display never uses an exponent, also as in
  Rust.
- **Exhaustiveness checking panicked** (index out of bounds) when a
  pattern named a variant of another type with a different arity, e.g. a
  user `enum option` matched with the prelude's `Some(_)`; the typeck port
  hit it on `prelude.kn`. *Fixed* in both checkers: an exhausted row is
  skipped.
- **`chan` is a keyword**, so it can't be a field name. The Rust AST's
  `chan` fields are `ch` in `ast.kn` (the dump still prints `chan`).
- **u128 now works**, and the lexer and parser use it directly (the
  four-limb `U128` workaround is gone).

## Gaps the lexer port hit

- **u128 was barely usable** (constants, formatting, `checked_*`).
  *Fixed:* u128/i128 constants, arithmetic, division, formatting,
  parsing, and `num.kn` methods (`tests/run/int128.kn`). The lexer now uses
  native u128.
- **An assignment couldn't be a match-arm body** (`Some(n) => v = n,`).
  *Fixed:* the parser now reads such an arm as a one-statement block
  (`tests/run/match_assign_arm.kn`).
- **`"}"` and `"{"` in string literals must be written `"}}"` and `"{{"`,**
  because every string literal interpolates. This is by design, but
  surprising when porting Rust code. A plain `"{"` silently starts an
  interpolation (in the punctuation table, it swallowed the following
  `", "` and dropped an element); the type error came from the array
  length. *By design; documented here.*
- **Unicode classes:** Kiln's `char::is_alphabetic` uses letter categories
  (`std::unicode::is_letter`), while Rust's uses the `Alphabetic` property
  (which also covers letter numbers and some combining marks). No file in
  the repository differs. An identifier with such a character would lex
  differently. *Fixed:* `char::is_alphabetic`/`is_alphanumeric` now use
  generated UCD tables and match Rust on every code point
  (`tests/run/unicode_alphabetic.kn`).

## Build pipeline performance
Debug builds split the IR into hidden-linkage shards, compiled with `clang -O0` in parallel. Unchanged shards are reused. Release builds use ThinLTO shards plus lld when available, and fall back to one `-O2` module. Std bodies are type-checked lazily. Use `--time-passes` for a per-pass breakdown, and set `KILNC_JOBS` to control parallelism. See bench/COMPILE.md.

## Release code generation
With `--release`, kilnc emits LLVM attributes for Kiln's guarantees (codegen.kn `end_release_fn`). Every function `f` gets an `f.v` body that takes small scalar arguments, thin references and `(ptr, len)` fat references by value, and returns 1/2/4/8/16-byte results by value. `f` itself keeps the uniform slot signature (function pointers and vtables still use it) as an always-inlined wrapper. See bench/RESULTS.md for the numbers.
