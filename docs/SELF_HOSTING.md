# Self-hosting plan

The compiler is written in Rust. The plan is to rewrite it in Kiln one
stage at a time, front to back. Each stage is checked differentially
against the Rust implementation of the same stage before anything
depends on it. The Rust compiler stays the reference (and the bootstrap
compiler) until the Kiln one can build itself.

## Layout

`compiler/` is an ordinary Kiln package (`kilnc`):

- `src/token.kn`: token kinds, keywords, the statement-ending rule.
- `src/lexer.kn`: the lexer (port of `crates/kiln_lexer/src/lexer.rs`).
- `src/ast.kn`: the syntax tree (port of `crates/kiln_parser/src/ast.rs`,
  same names, fields, and variant shapes).
- `src/parser.kn`: the parser (port of `crates/kiln_parser/src/parser.rs`),
  including error recovery and every diagnostic message.
- `src/debug.kn`: writes the AST in the canonical dump format.
- `src/escape.kn`: generated by `tools/gen_escape_debug.rs`; the code
  points Rust's `{:?}` writes as `\u{..}`, so string and char payloads
  in the dump are escaped the same way.
- `src/main.kn`: the driver. `kilnc <file.kn>...` prints the canonical
  token dump; `kilnc --ast <file.kn>...` prints the canonical AST dump.

Build it with `kiln build` in `compiler/`.

## Differential testing

Each stage gets a canonical text dump implemented on both sides. For the
lexer, that is `kiln_lexer::dump`, printed by `kiln lex --dump <file>`:
one line per token with its byte span and payload, then doc comments,
then errors. `crates/kiln_cli/tests/lexer_diff.rs` builds `kilnc`, runs
it on every `.kn` file in the repository, and requires its output to be
identical. That includes std, examples, tests, benchmarks, the compiler
itself, and the edge-case corpus in `tests/lexer/` (every lexical error
path, all literal forms, CRLF and Unicode whitespace). It runs with
`cargo test`.

For the parser, the dump is `kiln_parser::dump`, printed by
`kiln parse --dump <file>`: the pretty `{:#?}` of the `File` before derive
expansion, with each `Span { start, end }` collapsed to `start..end` on
one line, followed by one `error <start>..<end>: <message>` line per
diagnostic (lexer errors first, then parser errors in the order they were
reported). `crates/kiln_cli/tests/parser_diff.rs` runs `kilnc --ast` on
every `.kn` file in the repository plus the corpus in `tests/parser/`:
`syntax.kn` covers every syntactic form, and `errors.kn` covers the error
messages and recovery paths. The output must match byte for byte.

compiler through dumps only. Nothing in the Rust build depends on
`compiler/`.

## Gaps the parser port hit

- **The formatter continued the line after `import a::*`**, indenting the
  next item, because it read the trailing `*` as a binary operator.
  *Fixed* in `kiln_fmt` (test `glob_import_does_not_continue`).
- **Other formatter bugs:** `?Sized` printed as `+?Sized`, `pub(pkg)` as
  `pub (pkg)`, and a line after a type ending in a generic `>` was
  indented as a continuation (this had mis-indented parts of std).
  *Fixed*; `tests/parser/` is in the formatter corpus test again.
- **`{:?}` on f64 differed from Rust** (`1e16` printed as
  `10000000000000000.0`). *Fixed:* Debug switches to the shortest
  exponent form outside `1e-4 <= |x| < 1e16`, as Rust does
  (`tests/run/float_debug.kn`). Display never uses an exponent, also as in
  Rust.
- **`chan` is a keyword**, so it can't be a field name. The Rust AST's
  `chan` fields are `ch` in `ast.kn` (the dump still prints `chan`).
- **u128 now works**, but the lexer still uses the four-limb `U128`; the
  parser keeps it so the two stay in step.

## Gaps the lexer port hit

- **u128 was barely usable** (constants, formatting, `checked_*`).
  *Fixed:* u128/i128 constants, arithmetic, division, formatting,
  parsing, and `num.kn` methods (`tests/run/int128.kn`). The lexer still
  uses its four-limb `U128`.
- **An assignment couldn't be a match-arm body** (`Some(n) => v = n,`).
  *Fixed:* the parser now reads such an arm as a one-statement block
  (`tests/run/match_assign_arm.kn`).
- **`"}"` and `"{"` in string literals must be written `"}}"` and `"{{"`,**
  because every string literal interpolates. This is by design, but
  surprising when porting Rust code. A plain `"{"` silently starts an
  interpolation (in the punctuation table, it swallowed the following
  `", "` and dropped an element); the type error came from the array
  length. *By design; documented here.*
- **Unicode classes:** Kiln's `char::is_alphabetic` uses letter categories
  (`std::unicode::is_letter`), while Rust's uses the `Alphabetic` property
  (which also covers letter numbers and some combining marks). No file in
  the repository differs. An identifier with such a character would lex
  differently. *Fixed:* `char::is_alphabetic`/`is_alphanumeric` now use
  generated UCD tables and match Rust on every code point
  (`tests/run/unicode_alphabetic.kn`).
